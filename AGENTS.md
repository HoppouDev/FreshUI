# FreshUI

This is a standalone .NET 10 mod for Aether: a pixel-perfect, compact UI (see [README.md](README.md)).
Most of it is mixins and the resources they load; the initializer sets up its Gum screens (`src/Gum/`).

| Path | Purpose |
| --- | --- |
| `FreshUI.slnx` | IDE solution for the mod project. |
| `.vscode/`, `.mcp.json` | VS Code build, run and debug tasks (see Build and test), and the game's MCP server for agents. |
| `.gitignore` | Keeps the local client, test saves, build output, and IDE state out of Git. |
| `src/Startup.cs` | Mod initializer (Gum screens and their keys) and mod ID. |
| `src/HotReload.cs` | Rebuilds FreshUI's screens after a .NET hot reload (`./aether watch`). |
| `src/GuiScale.cs` | The GUI scale setting, shared by the legacy UI and Gum. |
| `src/Legacy/` | The legacy UI: the game's own UI, patched by mixins, and the helpers below (namespace `FreshUI.Legacy`). Being migrated to Gum screens (`src/Screens`) screen by screen, the hooks that stay moving to `src/Hooks`. |
| `src/Hooks/` | Mixins and helpers that aren't UI drawing (namespace `FreshUI.Hooks`): the routes that switch the game's screens off where Gum screens replace them (`GameScreensMixin`, `MenuScreensMixin`, `UserInterfaceMixin`). |
| `src/Legacy/Sharp.cs`, `src/Legacy/PixelSlots.cs`, `src/Legacy/Hud.cs` | Shared state and helpers: the pixel-snapping sampler, nine-sliced slots and icon scales, and the hotbar layout. |
| `src/Legacy/PauseMenu.cs`, `src/Legacy/KeyDefaults.cs` | The in-game pause menu's state and actions (hard-coded Esc and Start; its screens are Gum's), and FreshUI's keys (inventory on Q, grapple on E; the gamepad's full map off Start), set once. |
| `src/Legacy/SettingsScreens.cs`, `src/Legacy/AetherGraphics.cs` | The title menu's settings screen (routing by `menuMode`, Back; Gum draws the window over it), and Aether's internal graphics settings through an accessor. |
| `src/Legacy/PixelImages.cs` | Image buttons' art at even pixels: 2×2-texel art as drawn, single-texel art at whole screen pixels per texel (the list items' buttons as icons at the GUI scale's pixels per texel, laid out again). |
| `src/MomentumScroll.cs` | Scrolling momentum: wheel turns as velocity, glides stepped each frame (the game's scrollbars and `FreshScrollViewer`). |
| `src/Legacy/SdfText.cs` | Text from a signed distance field: loads the shader and atlas, and replaces each font's Andy Bold glyphs with them. |
| `src/Legacy/Mixins/` | C# mixins (namespace `FreshUI.Legacy.Mixins`), one per target class. Register new mixin types in the manifest. |
| `shaders/SdfText.fx`, `resources/shaders/SdfText.fxb` | The SDF text shader's source, and the D3D9 effect FNA loads, compiled from it with the Windows SDK's `fxc` (see the source's header). |
| `src/Gum/` | Gum in game: the host layers and screen registry (`GumHost`, `GumHostMixin`, `GumScreens`, and `GumRoutes`: which game screen a Gum screen replaces), elements drawn on the spot within the game's drawing (`GumInline`), the gamepad on its menus (`GumGamepad`) and on the HUD (`GumHudFocus`), its distance-field text (`GumText`), pixel grid (`UiPixels`), textures (`GumTextures`) and the automation tree (`GumUiTree`). |
| `src/Components/`, `src/Screens/` | Gum components (`FreshStyle`, the shared palette; `FreshButton`, `FreshIconTextButton`, `FreshPanel`, `FreshPanelButton`, `FreshValueButton`, `FreshWindow`, `FreshSeparator`, `FreshTextBox`, `FreshGameView`, `FreshLabel`, `FreshItemSlot`, `FreshIconButton`, `FreshTooltip`, `FreshToggleSwitch`, `FreshSlider`, `FreshColorPicker`, `FreshProgressBar`, `FreshScrollViewer`) and screens (`HudScreen`, `PauseScreen`, `SettingsScreen` with `SettingsTabs`, what's on each tab, `CommandPopupScreen`, `GalleryScreen`). |
| `shaders/GumText.fx`, `resources/gum/`, `tools/GenerateGumFont.cs` | Gum text's shader source, its compiled effect and font atlas (`TextSdf.*`), and the atlas's generator (`dotnet run --file tools/GenerateGumFont.cs -- --font ANDYB.ttf`). |
| `tools/sdf_font.py`, `resources/fonts/andy-sdf.*` | The SDF atlas generator (`uv run tools/sdf_font.py ANDYB.ttf resources/fonts`) and its output: the field and each glyph's rectangle and corner. |
| `aether.mod.json` | Mod ID, version constraints, entry assembly, initializer, mixins, and display metadata. |
| `icon.png` | Optional mod icon, packaged at the archive root. |
| `build/Aether.Mod.targets` | Shared reference, validation, packaging, and install targets. |

- Keep the mod ID, entry assembly, and type names in sync with the manifest.
- Keep C# sources under `src/` and use exact mixin signatures for the Terraria versions in `depends`.
- Add required mods to `depends` by manifest ID with a version constraint, such as `"shared-library": ">=1.2 <2"`.
  Aether checks these constraints on launch.
- Leave the generated Aether and Terraria version placeholders in place to use exact versions from the local client when packaging.
  Set a literal version or range to target a different version.
- Keep the local Aether checkout path and game binaries out of Git and the mod archive.

`PackMod` copies the manifest to the archive root and preserves files under `resources/`.
Use archive-relative paths in manifest entries such as `"mappings": "resources/mappings.json"`.
From C# use a resource-relative path such as `ModResources.OpenRead(Startup.ModId, "welcome.txt")` and dispose the returned stream.

## Build and test

Run `./aether setup` on Linux or macOS, or `.\aether.cmd setup` on Windows, to prepare the client without opening the game.
The launcher clones Aether into `.aether/client`, runs the checkout's setup if Terraria sources have not been generated, and builds the client and Aether API in the selected configuration.
Launching the mod directly also prepares the client on first use.
You need the checkout's setup prerequisites and the pinned Linux Terraria build.
If setup cannot find that build, see the cloned checkout's `AGENTS.md` for its `download` and setup instructions.

Use `AETHER_CONFIGURATION=Release` to select Release.
The launcher reuses the checkout and builds the client in the selected configuration on every run, which is quick when nothing changed.
After you pull new commits into `.aether/client`, the next run re-applies its patches and rebuilds the client.
Set `AETHER_REPOSITORY` before the first clone to use a different Git remote.
To use an existing built checkout, set `AETHER_ROOT` or put its path in `.aether-root`.
Relative paths are resolved from the mod repo.

- Open `FreshUI.slnx` in your IDE after setup.
- `dotnet build` checks that the mod compiles against the local client and API.
- `dotnet build -t:PackMod` creates the archive in the build output.
- `dotnet build -t:InstallMod` packages the mod and installs it alongside `aether-api.aethermod` into `.aether/saves/Mods`.
  Set `-p:AetherSaveDirectory=/path/to/test-saves` to install into a different profile.
- `./aether watch` (Linux, macOS; needs the ASP.NET Core runtime, which `dotnet watch` runs on) launches the game under `dotnet watch` with .NET hot reload: saved edits to FreshUI's own code apply to the running game, and `HotReload` rebuilds every Gum screen, the pause menu and the settings window, for prototyping UI without restarting.
  The project's `RunCommand` is the launcher, which keeps the agent's startup hook (`DOTNET_STARTUP_HOOKS`) out of its builds and passes it to the game; edits to mixins (merged into the game at startup) and rude edits restart it.
- `./aether -- -mixindebug` builds, installs, and launches with the local test profile on Linux or macOS.
  On Windows use `.\aether.cmd -- -mixindebug` or `.\aether.ps1 -- -mixindebug`.
- `AETHER_LAUNCH_OPTIONS` passes extra `aether launch` options through the launcher (Linux, macOS), such as `--profile` for Aether's allocation profiler (Linux; record with the MCP tool `game_profile`).
- In VS Code, the launch configurations (`.vscode/`) start the game from a task (Debug, Debug with hot reload under `./aether watch`, Widget gallery under `./aether gallery`, Debug with profiler), each serving the aether-game MCP server on port 47321 (`-aethermcp`, `.mcp.json`), and attach the debugger: pick `Aether.Bootstrap` from the list, since netcoredbg attaches only by process ID. Stopping the session ends the game.
  `PackMod` packages `FreshUI.pdb`, which Aether loads with the assembly, so breakpoints bind in FreshUI's code (mixins are merged into the game, so likely not in them).

For manual builds, `-p:AetherClientDirectory=/path/to/client-output` can point directly to the folder containing `Aether.Modding.dll` and `Terraria.dll`.
Set `AetherApiDirectory` to use an API build from another directory.
For installation, that directory must contain both `Aether.Api.dll` and `aether-api.aethermod` from the matching build.

The template references Aether API `0.1.0` by default.
Distribute the mod archive and tell users to install a matching Aether API archive separately.
To opt out, set `AetherUseApi` to `false` in the project and remove `aether-api` from `depends` in the manifest.
See `docs/api/index.md` in the Aether checkout for the API guide.

## Gum screens

FreshUI hosts [Gum](https://docs.flatredball.com/gum) screens in game, alongside the game's own UI (`src/Gum/`).

- **Adding a screen:** build its root element (a `ContainerRuntime` with Gum controls and FreshUI's components) in a class under `src/Screens/`, and register it from `Startup.Initialize` with `GumScreens.Register("fresh-ui:name", () => new MyScreen(), initiallyVisible, layer, showWhen, defaultFocus, hints, pageMove)`; the returned `GumScreen`'s `IsVisible` shows and hides it (for example, from a key with the Aether API's `Keybinds.Register`), and `showWhen` makes it follow the game's state (the pause menu shows while the game's settings window is open as the pause menu).
  A root implementing `IGumScreenUpdate` gets `UpdateScreen` every update while it shows (layout, reading the game's state).
  Screens are built once, on Gum's first update (the title menu), and kept between worlds. `fresh-ui:hud` is the live `HudScreen`, registered except in the widget gallery; Aether's inventory state determines which slots it presents, with Q and Esc handled by the game and `PauseMenu`.
- **Replacing a game screen** (`GumRoutes`; `StateKind` for game states of a kind): a Gum screen's `showWhen` from `GumRoutes.GameScreen<T>()` (an Aether in-game `UIGameScreen`: `GameScreens.Draw` no longer draws or updates it, and the Gum screen shows while the game asks for it; `Bind` shows it in the very frame the game first asks), `MenuMode(...)` (title menu modes: an empty menu screen), or `State<T>()` (a game `UIState` on the title menu's or fancy UI's `UserInterface`, which then neither updates nor draws it). A Gum screen that replaces one calls the game's methods for its actions.
  `GameIconButtons` (a `FreshGameView` in `HudScreen`) replaces every Aether icon-button screen and group (`UIIconButtonScreen`, `UIIconButtonGroup`: the side buttons, builder toggles, equipment page icons, PvP and team icons, loadouts, the minimap's buttons) by kind (`GumRoutes.GameScreens`): the game asks, Gum draws and handles them in its order, each as Aether's `UIIconButton` did (hover by the game's cursor, tick, press, right press, tooltip, its art at whole pixels), laid out by FreshUI once per screen (`SideButtons`, `PageIcons`).
  `HudScreen` (`HudScreen.Equipment.cs`) replaces the equipment page (`UIEquipmentSlots`): armour, vanity and dyes in three columns and rows 46 apart on the art's grid, each slot handled by `ItemSlot.Handle` as the page's were (a locked slot takes no item, `Main.armorHide` while used), the accessories' visibility toggles, the loadout buttons (the game's call, which `GameIconButtons` draws), the defense counter and, where the inventory has no room for it, the achievement card (both drawn by the game in the HUD's game view, at whole pixels).
  It also replaces the misc equipment page (`UIMiscEquipSlots`: pet, light pet, minecart, mount and hook with their dyes, the pet and light visibility toggles and the minecart upgrade's; `CornerToggle` for all the slots' corner toggles) and the NPC housing page (`HudScreen.Housing.cs`, `UIHousingPage`: the housing query and a head per town NPC type in `FreshItemSlot`s down the first column, 46 apart, new columns leftwards; hover names, a click picks one up to house it; the gamepad's points and housing cursor as the game's).
  `HudScreen.Containers.cs` replaces the open container's slots (`UIChestSlots`: a chest, the piggy bank, safe, defender's forge or void vault, scrolled past 40; `UIShopSlots`: an NPC's shop) on the inventory's grid above it, each handled by `ItemSlot.Handle`, and `HudScreen.ChestControls.cs` the chest's controls (`UIChestControls`): its name over its slots and its buttons (Loot All, Deposit All, Quick Stack, Restock, Sort, Rename / Save, Cancel) as `FreshValueButton`s in a column beside them, calling `ChestUI`'s actions (the mouse through Gum; the gamepad on the game's link points, A at the focused button). With a keyboard a rename is typed in place, in the name (the game's own typing for a rename with no on-screen keyboard up); with the gamepad it's the game's on-screen keyboard.
  `HudScreen.Crafting.cs` replaces the crafting lists (`UIRecipeList`: the available recipes in a column scrolling to the focused one, gold, smaller further from it, and its ingredients beside it, laid out by the game's offsets, which `QuickCraftingLayoutMixin` centres; `UIRecipeGrid`: the classic grid and its arrows): `FreshItemSlot`s where the game placed its icons, hovered and clicked as the game's (`Main.HoverOverCraftingItemButton`, a grid click focusing that recipe), the CRAFT shortcuts set before each so the gamepad's crafting points are the game's. A recipe filter's title is Gum text; the plain list's "Crafting" isn't shown. The crafting toggles beside the coins are icon buttons (`GameIconButtons`, placed by `CraftingControlsMixin`).
  `CraftingWindow` (a `HudScreen` child) replaces the crafting window (the game's `NewCraftingUI`, its modern grid, routed by `GumRoutes.State`, which the window's own `UserInterface` then neither updates nor draws): the item categories as `FreshPanelButton` tabs (the game's icons, `CentreIcon`; one open at a time, gold), a `FreshPanel` with the window's title (or its crafting station's) and a search box (a `FreshPanelButton`: a click starts typing, the game's own, `PlayerInput.WritingText` and `Main.GetInputText`, Enter, Esc or a click elsewhere ending it; right-click clears it), the chosen or hovered recipe with its ingredients and how many of each the player has (green, or red when short), with the Guide the item to look up and what the recipe needs, and every recipe in a `FreshScrollViewer` grid, those the player can't make dimmed (`FreshItemSlot.SetItem`'s light). Its state stays the game's window's (recipes, categories, search filter, chosen recipe), through compiled accessors to its private members; recipes and ingredients are hovered and clicked as the game's (`HandleCraftSlot`, `ItemSlot.HoverOverrideClick`) at the game's cursor, and the window's gamepad points (page 24) are placed on its controls (a wide one's under the focus, so moves by position reach it), the grid scrolling to the gamepad's slot. With the gamepad, the search takes the on-screen keyboard (`VirtualKeyboardScreen`).
  `HudScreen.ShopInfo.cs` replaces a shop's header (`UIShopHeader`: "Shop" over its slots, the price adjustment from the NPC's happiness, its face and percentage, beside them, the savings under those), the reforge price (`UIReforgeCost`) and the reforge and Guide slots (`UISingleSlot`, routed per instance, where the game places them, handled by `ItemSlot.Handle`); the savings and the price (coins in their colours, the game's chat text) are drawn by the game in the HUD's game view. `UIGameItemSlot`, whose screens are all Gum's now, is no longer restyled.
  `HudScreen.NpcChat.cs` replaces the NPC chat and sign box (`UINpcChat`): a `FreshPanel` at the top of the screen, sized as the game's, with the interactions (Shop, Happiness, Quest…) as `FreshValueButton`s along its bottom, four to a line (the mouse through Gum; the gamepad on the game's points 2500 and on, A on the focused one), and the game's part drawn in a `FreshGameView`: the text the game prepares (`NPCChatPanel`, wrapped, its chat tags parsed once a line; a sign being edited with its caret and IME), the portrait, the corner item (Aether's `UINpcChatCornerItem`), prices and notifications.
  `StylistWindow` and `DresserWindow` (`HudScreen` children) replace the Stylist's hair window (`UIStylistWindow`: the hair colour's `FreshColorPicker`, Buy with its price and the savings over it, Cancel, and fifteen hairstyles at a time as `FreshPanelButton`s with a bald head wearing each, drawn by the game, paged by the arrows or the wheel) and the dresser's clothes window (`UIDresserWindow`: the chosen part's `FreshColorPicker`, the voice's pitch as a `FreshSlider` in 21 steps, Change and Cancel, the player as they'd look on a button that cycles the clothing style, a voice button that cycles and sounds the voice, and the six parts as buttons with the game's icons). Their colours stay the game's `Main.hBar`, `sBar`, `lBar` and `selColor`, and the game's internal fields and methods are reached by compiled accessors. `HudPoints` places the HUD's Gum controls on the game's gamepad points (A on the focused one acts) and gives their areas in UI units.
  `HudScreen.ResourceBars.cs` presents the player's life and mana (`UIResourceBars`, in each style it lays out: classic, framed, bars): Aether's layout (`UpdateState`, run here), each piece a Gum sprite where the style places it and the "Life"/"Mana" texts Gum text, hovering life or mana showing its numbers. `HudScreen.Buffs.cs` replaces the buffs (`UIBuffBar`, the row in the top left corner where the hotbar was, eleven to a line; `UIBuffColumns`, under the misc equipment page, with gamepad points 9000 and on): each icon a Gum sprite with its time left under it, brightening while hovered, cancelled by a right-click (with the gamepad, A in the inventory), its name and tooltip shown while hovered.
  `HudScreen.Minimap.cs` draws the minimap's frame and its zoom buttons' hover art as Gum sprites (`UIMinimapFrameMixin` hands them over in place of Aether's `DrawForeground`; the dark square under the map and the buttons' handling stay the game's, as the map is drawn between them). `HudScreen.InfoAccs.cs` replaces the info accessories' readouts (`UIInfoAccs`: the game works out each row and hands it over): each row's icon a Gum sprite and its text Gum text in the row's colours (outlined in its shadow colour, smaller where it's too wide), the icons lined up with the inventory open, a click hiding or showing a row, hovering an icon naming it.
  `HudScreen.Invasion.cs` replaces an invasion's or event's progress (`UIInvasionProgress`, shown and faded as the game's): a `FreshPanel` in the event's colour with its icon and name, and one under it with the wave (or "cleared") text over a `FreshProgressBar`. `HudScreen.Notifications.cs` replaces the notifications (`UINotifications`), stacked upwards from above FreshUI's hotbar: "achievement unlocked" as a `FreshPanel` with the achievement's name and icon, brighter while hovered, a click opening it in the achievements list; other kinds (a friend asking to join) drawn by their own code in a game view. `HudScreen.Banners.cs` replaces the banners to claim (`UIBannerList`, `UIBannerGrid`) as the crafting lists: `FreshItemSlot`s with the claimable counts, the game's `BannerClaimingUI` keeping its state. `HudScreen.Death.cs` replaces the death screen (`UIDeathScreen`, its `UpdateState` run here): "You were slain", the coins dropped and the countdown as Gum text in the death colour, the respawn skip prompt (with the jump button's glyph) drawn by the game in a game view.
  `HudScreen` replaces Aether's inventory screens (`UIInventoryGrid`, `UICoinAmmoSlots`, `UITrashSlot`): it presents those slots on its grid and, while the game's cursor (the mouse, or the gamepad's navigator) is on one, claims the mouse and runs the game's `ItemSlot.Handle` (clicks, shift-click, stacking, right-click hold, tooltips), as Aether's slots did; it also replaces Aether's hotbar (`UIHotbar`: its slots, a click selecting one unless the hotbar is locked or the held item busy, the held item's own slot when it's further in the inventory, and its name above the slots in its rarity's colour, shown when the held item changes while the hotbar is shown and then faded out). The gamepad moves between them by Gum's focus (`GumHudFocus`) on the game's points.
- **Drawing:** Gum has two layers. HUD screens (`GumLayer.Hud`, in a world only) are drawn by one retained mod UI layer (`fresh-ui:gum`, Aether's `RetainedUi`), over the HUD and under mouse text and the cursor, suspended where the game's mod UI is (menus, settings, the full-screen map, hidden HUD); its surface updates Gum every update.
  Overlay screens (`GumLayer.Overlay`: menus) are children of a root of their own on a layer of their own, drawn by `GumHostMixin` once a frame: in a world before mouse text, and otherwise at the head of `Main.DrawCursor` (the title menu, and the settings window and fancy UIs, which stop the interface's layers before mouse text). Where the HUD's layer didn't update Gum, `GumHostMixin` does after `Main.Update`.
  Each draw ends and restarts the game's sprite batch around Gum's. Gum takes the mouse only over an interactive Gum element (a menu's full-screen backdrop is one, so a menu is modal), so elsewhere the game gets the click.
- **Pixels and art:** layout is in UI pixels, one pixel of the game's UI art (2×2 texels), and Gum's camera draws each as `GuiScale.Current` screen pixels (`UiPixels`), so the art stays even and follows the GUI scale setting.
  Components name the game's textures by asset name (`Images/Inventory_Back`, `Images/Item_22`), loaded through `GumTextures`.
- **Components:** FreshUI's restyle Gum's Forms controls with the game's art, keeping their behaviour (events, focus, automation): `FreshButton` (button backing), `FreshIconTextButton` (a `FreshButton` with an icon before its text, the pair centred; the icon tinted as the text), `FreshToggleSwitch` (a `ToggleButton`: the scrollbar pill as its track, blue off and teal on, and the settings toggle's filled circle as a knob that slides, a pixel inside the track), `FreshSlider` (a `Slider` in the switch's art: the pill track, filled in teal up to the round knob, gold while hovered, dragged or focused, which it tracks itself as Gum's Slider doesn't update its state for them; snapping with `IsSnapToTickEnabled`), `FreshScrollViewer` (a `ScrollViewer`: the game's scrollbar track and handle, no arrow buttons; the wheel glides with `MomentumScroll` unless `SmoothScrolling` is off, `WheelStep` UI pixels a notch).
  `FreshPanelButton` is the menus' button: the game's panel art in `FreshStyle.Button`, lit (`ButtonLit`, a gold border) while hovered, focused or `IsChosen` (an open tab), with the menus' tick; `AlignTextLeft` makes it a list's row, and `SetIcon` and `TextColor` an option button as the world creation's (an icon at its left, dimmed while neither lit nor chosen, and the option's colour; centred text centres in the space after the icon). `FreshValueButton` is a setting's value as text that acts when clicked (a choice that cycles, a key to rebind): no panel, right-aligned muted text, gold while hovered, focused or `IsLit`. `FreshSeparator` is the world creation's rule between groups (its separator art in pale blue), and `FreshTextBox` its Name and Seed fields: a Forms `TextBox` in the panel button's look with an optional `Label` before the text and a muted placeholder, lit while hovered or typed in (the mouse doesn't clear a text field's focus as it does the gamepad's; Aether's synthetic `type` fills the game's own text buffer, not FNA's text input Gum reads, so automation sets its text with `set_text`). `FreshWindow` is a window's title tab over its panels (`FreshPanel`). `FreshSlider.Ramp` makes a colour bar: its track shows a colour at each value (the cursor colour settings); `FreshColorPicker` is three of them as hue, saturation and lightness, editing a colour kept elsewhere (`Get`, `Set`, `Sync`), lightness at least `MinLightness`. `FreshProgressBar` is the slider's track filled in teal up to its `Value`, fading with `Opacity`. `FreshGameView` draws game content in Gum's draw order (its `Draw` gets the game's sprite batch, begun in UI units with the sharp sampler, and its area): chat text with its tags, portraits, coins; its renderable has a batch key of its own, so Gum ends its batch before it and what Gum draws later goes over it. `FreshTooltip` shows an element's text by the cursor while it's hovered (and, attached to a control, under it while it has the gamepad's focus), outlined with the hotbar's drop shadow, on top of the overlay's root (Gum's popup root isn't drawn in game), and gone once its element is no longer shown (a screen closing, a list rebuilt).
  With the gamepad (`GumHost.GamepadEnabled`, on while an overlay screen with a `defaultFocus` shows: the menus, the widget gallery), Gum's own focus navigation moves between them and A activates; focused, a button's text and a switch's or slider's knob are gold (the game's selected-item colour), `FreshIconButton` (an `IInputReceiver` of its own) shows its outline (or, with `HasBacking`, the lit panel behind it), a scroll area's handle is gold and the right stick scrolls it, and a slider steps by 1% on the D-pad and 10% on the bumpers (by whole ticks when it snaps).
  `GumHost.Animate` steps an animation (the knob's slide, a scroll's glide) every frame before Gum draws, by the time since the last frame, while it runs.
- **Widget gallery:** `./aether gallery` (Linux, macOS) runs `./aether watch` with `-freshuigallery` and the MCP server on port 47321: the client opens on `GalleryScreen` (`fresh-ui:gallery`, every component in a grid of panels, modelled on Gum's all-controls showcase) in place of the title menu, for prototyping components with hot reload and driving them over MCP (`game_ui_layout`'s `gum` tree, `game_ui_action`, `game_screenshot`).
  `GumGallery` keeps the title menu on an empty menu state then, and the toolbar's UI scale slider sets `GumHost.ScaleOverride`, whole screen pixels per UI pixel, for the gallery only.
- **Gamepad on menus** (`GumGamepad`): a menu's controls are one spatial-navigation zone (`GumGamepad.SpatialZone`, a Forms `Panel`; Gum's default is tab order), so the D-pad moves the focus to the nearest control that way. Using the gamepad focuses the screen's `defaultFocus`, the mouse clears the focus, and while the gamepad drives a menu the mouse hovers nothing (Gum's cursor is moved off the canvas). The game's instruction bar shows the focused control's hints, then the screen's, from a link page of FreshUI's own (31100) whose one point (the game's cursor) follows the focus; its page moves (LT/RT) go to the screen's `pageMove`, and on the title menu B (the inventory key) is the menu's back (`UILinkPointNavigator.Shortcuts.BackButtonInUse`, as the game's own title page sets it). A `FreshScrollViewer` with `IsFocusable` off passes the focus coming onto it to its first control in view (a list's rows).
  Add a component to the gallery as a `Cell` in `GalleryScreen`; its rows centre a control and its label (`Row`).
  The components' art is the game's 2×2-texel art at half a UI pixel per texel, and moving parts (the slider's knob) snap to whole screen pixels, so they stay even at every UI scale.
  The switch's and slider's tracks are the scrollbar pill made 9 pixels tall by repeating an interior row (`GumTextures.Taller`; the art is 8, and the 7-pixel knob sits a pixel in from each edge), drawn as three sprites (`FreshPill`: ends and stretched middle, each the art's full height), not a nine-slice: stretching the art's 2-pixel middle to 3 doubles a row unevenly, and Gum's nine-slice places its bottom slices a screen pixel off for this art. Place pixel art at whole UI pixels (the gallery's rows have the parity of their art).
  Hot reload can report success without applying an edit (one adding a method that changed code calls), and has crashed once on an edit to code that runs every update (a garbled `TypeLoadException`); when the gallery doesn't show an edit, quit it and save a file to restart it.
- **Text** is drawn from a signed distance field (`GumText`: Gum's font loading goes to one atlas, in FreshUI's resources), with procedural weights, italics, outlines, gradients and drop shadows.
- **Remote automation:** `GumUiTree` lists the Gum elements in Aether's `game_ui_layout` as their own tree (`gum`, owner `fresh-ui`), separate from the game's retained UI, with IDs like `gum:12`, each component's screen, values (slots' items and counts, toggles' state, sliders' position), whether it has the focus, and actions (`activate`, `secondary`, `set_value`, `set_text`); `game_ui_action` and component screenshots (`game_screenshot` with `component_id`) work on them.
  Gum skips input while the window is inactive, so under Aether's synthetic input `GumHost` counts the window as focused for Gum's update.

## How it works

- `PixelArtMixin`: FreshUI's sharp UI, always on: Aether's UI sampler hook (`Aether.Graphics.PixelArt.Sampler`, the batch's own sampler, linear as in vanilla) answers `Sharp.Snapped` instead, point sampling that also has FNA's SpriteBatch put sprites' edges on whole pixels (`SamplerState.PixelSnapEXT`, from Aether's patch to FNA). Fonts keep linear filtering (Aether sets their textures' `SamplerEXT`).
- `MenuScreensMixin`, `UIIngameOptionsMixin`, `IngameOptionsMixin` (with `SettingsScreen`, `SettingsTabs`, `SettingsScreens`): one tabbed settings window for the title menu and the game, a Gum screen on the overlay (`fresh-ui:menu-settings` and `fresh-ui:settings`), in place of Aether's in-game window and title-menu settings pages.
  `MenuScreens.GetScreen` answers `MenuSettingsScreen` (empty: Gum draws the window over it) for Settings (mode 11) and every settings page's mode (112, 1112, 1111, 111, 28, 2008, 44110, 26, 1125, 25, 252, 1127), opening the tab that page's settings moved to, so code that opens a page by mode (Keybindings' Back) lands on the window; Language (1213) stays Aether's screen.
  In game, `UIIngameOptions.DrawWindow` draws nothing in place of Aether's window (with the rest of what it draws), and `IngameOptions._GUIHover` is the Gum window's area (`PauseMenu.Area`).
  It's styled as the Mods window (`ModsScreen`): a title tab over two panels (`FreshWindow`), the tabs (General, Display, Graphics, Effects, Interface, Volume, Cursor, Keybindings) in the left one with the window's actions under them (Back; on the title menu, Language and Back), and the open tab's name and rows in a `FreshScrollViewer` in the right one, under muted group headers; the open tab is kept between openings.
  A row isn't a button: it's the setting's name at the left and its control at the right, lit (a panel with a gold border) only while hovered or while its control has the focus, and a click anywhere on it is its control's. On/off settings are `FreshToggleSwitch`es (`Switch`; their name is what the game's two texts for the states share up to a word's end, `SettingsTabs.Pair`, or its "Name: {0}" text without the value, `FormatName`), settings with several values show their value as a `FreshValueButton` that cycles them (`Toggle` splits the game's "Name: Value" text, `Cycle` takes the two), actions a chevron (`Button`), and sliders and the cursor's colour bars a `FreshSlider`.
  The Keybindings tab is the game's key bindings menu merged in: the input profile (cycled), Activate Set Bonuses and Quick Trash, then the keyboard's bindings in the menu's groups (gameplay, map, hotbar: each binding's name and keys from the game's own row, `UIKeybindingListItem`'s `GetFriendlyName` and `GenInput` through reflection; a click on the keys has `PlayerInput.ListenFor` take the next key, the keys gold until then, unbound ones grey; each group's Reset to Default, Double Tap Dash and Pan Control rows), and a Gamepad Bindings row that opens the game's menu for the gamepad's. The cursor colour bars are `FreshSlider`s with `Ramp`s from vanilla's `DelegateMethods.ColorLerp_HSL_*`.
  Group headers and the Display and Graphics tab names are FreshUI's own English text; the rest is the game's and Aether's.
  Each setting appears once, with vanilla's texts and behaviour (Map Enabled only on the title menu; resolution and fullscreen applied after the frame, as in vanilla's in-game window); Aether's graphics settings are `internal`, so `IGraphicsSettingsAccess` and `AetherGraphics` reach them through accessors.
  On the gamepad (`GumGamepad`) the focus moves between tabs and rows by position (left from a row to the open tab), a focused slider steps by 1% on the D-pad and 10% on the bumpers, a focused row scrolls into view, LT/RT go to the previous and next tab, and B is the inventory key (in game, back to the pause menu, then closed; on the title menu, the menu's back). The focus starts at the open tab, or where it was (back from key bindings).
- `MainMixin`, `PlayerMixin`, `IngameOptionsMixin`, `IngameFancyUIMixin`, `PlayerInputMixin` (with `PauseMenu`, `KeyDefaults`): a Minecraft-style pause menu in game.
  It is vanilla's settings window as far as the game knows (`Main.ingameOptionsWindow`, so Autopause pauses it), drawn as Gum screens over the game dimmed, `PauseScreen` or, after its Settings, `SettingsScreen` (each shown by `PauseMenu.ShowsPause` or `ShowsSettings`): Back to Game, Achievements | Mods (Aether's internal `UIModList`, made by reflection and opened as a fancy UI), Settings | Invite Friends (where invites work), Save & Exit.
  Esc, and the gamepad's Start, are hard-coded, not key bindings: at the end of `Main.DoUpdate_HandleInput` (after the keyboard is read, before chat, which closes on Esc itself), unless typing, rebinding or on the title menu, a press calls `Player.ToggleInv`, which closes whatever is open as the inventory key does, and whose `OpenInventory` call (nothing open) opens the pause menu instead while Esc is being handled (`PauseMenu.HandleEscape`).
  `ToggleInv`'s `IngameOptions.Close` call goes back from settings opened from the pause menu before it closes the window (also while dead, `TryOpeningInGameOptionsBasedOnInput`, where the inventory key opens the pause menu).
  `MainMixin` drops the Settings button at the bottom right (`DrawInterface_29_SettingsButton`'s `DrawSettingButton` call): Settings is the pause menu's.
  Closing the window leaves the inventory as it was when it opened (vanilla always reopens it); achievements, mods and key bindings opened from the window reopen it at the same view when they close (`IngameFancyUI.Close`), and the Mods window's Back closes it in game rather than going to the title menu.
  On the gamepad, the pause menu's focus starts at Back to Game, or where it was since the menu opened (back from the settings).
  `KeyDefaults` puts Inventory on Q (taking Esc, and the E an earlier version added, off it) and Grapple on E (taking that version's Q off it) in every input profile's keyboard modes, and takes the full map off Start in the gamepad modes (in play onto Back, which the map style gives up, where Back isn't another action's), once per version (`FreshUIKeyVersion` in the config, kept across `Main.SaveSettings` with the GUI scale), adding each key only where no other action has it.
- `TitleMenuScreen` (`fresh-ui:title-menu`, an overlay screen taking the gamepad): the title menu's own screens (every Aether `UIMenuScreen`: the main menu, multiplayer, joining and hosting, the delete confirmations, connection status and errors, language…) drawn as Aether's items: Death Text (`GumText.DeathTextSize`) thinly outlined in black with a soft drop shadow (`GumText.SetDropShadow` with a blur), faded in the menu's tint (Aether's premultiplied colours made straight, as Gum's text takes them) until hovered or focused, when it grows from 0.8 to full size and turns gold (labels whole). The main menu is spaced as vanilla's (52 units a line, Aether's is 45), less while the window is too short. Each item is a Forms `Button` with no backing, Aether's item's size (its text's width, 50 units a line) where Aether's screen puts it, its text kept up to date (a text field's typing and caret are the screen's), disabled as the item is, a click or A doing what the item does (through `MenuPreview.Act`, as Aether's items); labels are Gum text; the loading tips the connecting and loading screens drew are drawn in a game view. Aether's screen keeps its per-frame work and Back (`MenuScreens`) and is no longer drawn or updated (`GumRoutes.StateKind`: every `UIMenuScreen`, on Aether's own `UserInterface`).
- `SelectScreen`, `PlayerSelectScreen`, `WorldSelectScreen` (`fresh-ui:player-select` and `fresh-ui:world-select`, routed by `GumRoutes.State<UICharacterSelect>` and `<UIWorldSelect>`; the game's states still load the players and worlds when they open): a `FreshWindow` under the logo with a row per entry in a `FreshScrollViewer`, in the game's order, and Back and New under it, B going back. Both lay their rows out alike (`SelectScreen`'s helpers): the picture (drawn by the game in a game view, 29 UI pixels square) at the top left, 5 pixels inside the border as on every side; beside it the name level with its top and a details line ending level with its bottom, with an aside at the line's right; and under it the buttons, a band a pixel under the picture and 4 over the border, delete at its right end. A row lights (a gold border) while the cursor is over it or one of its buttons has the focus. A player's row has the portrait (the game's `UICharacter`), life and mana (the game's heart and star) and difficulty, time played as the aside, and `FreshIconButton`s for play, favourite, cloud (where the cloud is available), rename (the game's on-screen keyboard) and delete (not for favourites; the confirmation is the title menu's), calling `PlayerFileData` as the game's rows. A world's row stands for one of the game's own `UIWorldListItem`s: its icon (with its badges), size and difficulty (in its colour), creation date as the aside, and its buttons (play, favourite, cloud, seed, rename, delete) calling that item's handlers (the creative mismatch's rejection, multiplayer's next step, copying the seed). The rows' buttons are the game's list buttons without their frame (`PixelImages.Icon`), a texel a UI pixel, a little dim at rest and backed by the lit panel while hovered or focused (`FreshIconButton.HasBacking`), named for automation and their tooltips, which show under a button while it has the gamepad's focus.
- `GameUiMirror`: a game screen (an element tree the game built and laid out, with its handlers, texts and state) drawn and operated by Gum, each element getting a FreshUI component at its laid-out place in the tree's order: option buttons (`GroupOptionButton`, their icon, chosen while selected), difficulty buttons (chosen for the player's), image buttons (`UIColoredImageButton`: their icon in its colour, chosen while selected), text panels, name plates and elements the game acts on clicks for (a handler, or the type's own mouse down or click) are `FreshPanelButton`s; colour sliders (`UIColoredSlider`) `FreshSlider`s on the game's value and colours; lists (`UIList`) a `FreshScrollViewer` holding their items (the game's own scrollbars dropped); panels `FreshPanel`s, separators `FreshSeparator`s and texts Gum text in the game's size (Andy Bold at the font's em) and colour on its baseline; other leaves (previews, portraits, hair styles) are the game's drawing in a game view (in a list, moved with its scroll and clipped to its view), with an invisible `FreshIconButton` over them where the game listens. Gum's clicks (the mouse, A on the focus, automation) reach the element as the game's mouse down, up and click, and hovering or focusing it as its mouse over and out (descriptions). The state itself is routed off; the mirror runs its update (its elements' own per-update work), lays it out again when the screen's size or the tree changes, and rebuilds when the tree changes.
- `WorldCreationScreen` (`fresh-ui:world-creation`, `GumRoutes.State<UIWorldCreation>`): the world creation by `GameUiMirror` (name and seed, size, difficulty and evil, the preview, the description, Back and Create), the secret seeds' ring and particles drawn by the game over it, B the game's back.
- `CharacterCreationScreen` (`fresh-ui:character-creation`, `GumRoutes.State<UICharacterCreation>`): the character creation by `GameUiMirror` (categories, colour pickers, hair and clothing styles, voice, difficulty, name, the preview, Back and Create), the hovered button's name by the cursor as the game's own `Draw` shows it, B the game's back.
- `WorldLoadScreen` (`fresh-ui:world-load`, `GumRoutes.State<UIWorldLoad>`): the world generation's progress in the game's ornate style, built of Gum sprites at the game's layout: the pass's message (with the cancel and secret seed lines the game adds) in Death Text's size, with a drop shadow, over the game's frame for the world's evil (`Images/UI/WorldGen/Outer_*`), the whole generation's progress in the evil's colour and the pass's in gold (`ColoredRectangleRuntime`s, each with the game's darker end pixel), and the game's tips (`Main.gameTips`) in a game view; the state's update still runs.
- `ModsScreen` (`fresh-ui:mods`, an overlay screen taking the gamepad): Aether's Mods window (its internal `UIModList`, routed by `GumRoutes.StateKind` on its type: on the title menu, and in game as a fancy UI from the pause menu, modal over the game dimmed) in the settings window's layout: a "Mods" `FreshWindow` over two `FreshPanel`s. The left one has a `FreshTextBox` search (names, IDs and authors, as Aether's), the loaded mods as `FreshPanelButton` rows (the mod's icon, filtered smoothly as a picture, its name, and its ID and version; the chosen one lit), how many show, and Open Mods Folder and Back at its bottom; the right one has the chosen mod's details as wrapped Gum text (name, ID and version, authors, description, contributors, licence, shown as written) and its Homepage and Source links (http or https only). Back, Esc (unless it ends the search's typing) and B go to the main menu, or in game close the window (back to the pause menu). With the gamepad, the search takes the on-screen keyboard (`VirtualKeyboardScreen`).
- `MainMixin`: `Main.UIScale`'s setter stores FreshUI's GUI scale (`GuiScale`) whatever it's given, so the title menu and the game share it.
  The GUI scale is Auto (one below the largest that fits, vanilla's UI scale limit; the largest crowds the screen) or 1, 2, 3… screen pixels per art pixel (2×2 texels), so the UI scale is a half-step.
  It's kept in Terraria's `config.json` as `FreshUIGuiScale` (until then, the vanilla UI scale's nearest step); `MainMixin` puts it back after `Main.SaveSettings` clears the config to write the game's own settings.
  The settings window's Display tab has a button that cycles it (in place of vanilla's UI scale slider): Auto, 1, 2… the largest, Auto.
- `CursorMixin`: the cursor is drawn at the UI's size, its scale read as 1 where it's drawn (vanilla's `cursorScale` pulses between about 0.8 and 1.1).
- `InventoryLabelMixin`: the open inventory's "Inventory", "Coins" and "Ammo" labels aren't drawn (the first three calls of that `DrawString` overload in `DrawInventory`): the coin and ammo row is told apart by its colours.
- `ItemSlotMixin`, `CoinSlotMixin`: `ItemSlot.Draw` draws slot backgrounds (52×52 textures at a slot's position) nine-sliced (plain backgrounds swapped: coin slots' for `Inventory_Back6`, olive, ammo slots' for `Inventory_Back8`, teal, the inventory's selected hotbar slot's for `Inventory_Back10`, and the hotbar's for `Inventory_Back9` and, for its selected slot, `Inventory_Back10`, as the inventory's hotbar row; the context and slot come from injects at its head and return), and its item icons and coins at a multiple of ½ screen pixel per texel that fits the slot (`PixelSlots.Slot` tells `DrawItem_GetColorAndScale` and `DrawItemCoin` they're in one).
- `UIIconButtonMixin`, `DefenseCounterMixin`, and the rest of `ItemSlot.Draw`'s sprites (empty slot silhouettes, the trash can, overlays): pixel art drawn at fractional scales gets a whole number of screen pixels per art pixel through Aether's `SpriteBatch.PixelScaleEXT` (`Sharp.WholePixels`), set only while they draw: the nine-sliced slot backgrounds must keep their exact sizes.
- Slot sizes in `PixelSlots.DrawSlot` and the hotbar: slots on the art's pixel grid (2 UI units a pixel): whole-pixel sizes (0.85 slots are 44 units, not 44.2).
- `MainMixin`, `UIEquipmentSlotsMixin`: a chest's slots a row lower (`MainMixin` raises `Main.invBottom` from 258 by one row, `ChestDrop`) and the equipment page (columns and rows 46 apart, with no extra gap before the accessories; slots, accessory toggles and the defense counter) on the art's pixel grid, with one art pixel between slots.
- `GameIconButtons` (with `SideButtons`), `AchievementAdvisorMixin`: the quick stack, sort, bestiary and emote buttons in a grid of two 32-unit columns 34 apart where vanilla's coin and ammo columns were, starting just under the advisor's card (with a chest open, beside it as vanilla's, a row lower with it; their areas are lambdas, so they're wrapped once, when each button first updates), and the hotbar lock moved from the screen's left edge into that grid, below them (the Gum `HudScreen`'s); and the achievement advisor's card at whole pixels (its scales, 0.75 and 0.35, rounded), its border centred over the grid on whole screen pixels (at that scale its art doesn't share the slots' grid) with its top on the inventory's (`InventoryLabelMixin` places it).
- `GameIconButtons` (with `PageIcons`, `SideButtons`): the camera, housing and equipment page icons above the equipment columns centred over the columns, on the art's pixel grid (so art an odd number of pixels wide sits half a pixel left of centre); and the builder toggles (block replacement, torch swapping, then the builder accessories') moved from the left edge into the side-button grid after the hotbar lock, two to a row, packed past hidden ones and following the bestiary row while a chest is open. Their areas are wrapped once, when `GameIconButtons` first meets each group.
- `SdfTextMixin` (with `SdfText`): at the start of each frame's draw, each loaded font (`MouseText`, `ItemStack`, `DeathText` and the two combat fonts) not yet replaced gets Andy Bold's glyphs from the distance field atlas (`DynamicSpriteFont.SetCharacterImage`), at a size and offset fitted to that font's own glyphs (`SdfText.Fonts`), so text measures and wraps as before.
  The atlas texture carries the shader (`Texture.EffectEXT`) and linear filtering (`Texture.SamplerEXT`); characters Andy Bold lacks keep the font's images.
  Fonts load asynchronously and again with resource packs, hence the per-frame check.
- `UIImageButtonMixin`, `UICharacterListItemMixin`, `UIWorldListItemMixin` (with `PixelImages`): `UIImageButton`'s image and hover border; art with a texel per pixel (detected once per texture: not every 2×2 block one colour) is drawn at the largest whole number of screen pixels per texel up to the UI scale, centred where it was. The character and world list items' buttons (that art) are drawn as just their icons (a copy of each texture without the 2-pixel frame, the fill and the icon's shadow on it) at the GUI scale's screen pixels per texel, laid out again after each item's constructor at that size, 2 units apart with the labels after them (their capitals level with the buttons' middle, `SdfText.MouseTextCapMiddle`), the item taller by what they gained and its left column as far in as the delete button on the right; `SetImage` (favourite, cloud) keeps that size.
- `UIListMixin`, `UIScrollbarMixin` (with `MomentumScroll`): a wheel turn's change to a scrollbar's view position (`UIList.ScrollWheel`) is a third of vanilla's (`MomentumScroll.StepScale`) and becomes velocity instead: each scrollbar's `DrawSelf` moves it along an exponentially decaying glide (10 per second, covering the step) by the time since its last frame, stopping at the list's ends, when nearly still, or when the handle is dragged. A turn while the bar already glides its way adds more, up to twice its step (`MaxBoost`) once the glide is as fast as a turn, doubling the fastest scroll. Turning the wheel the other way stops the glide first.
- `BigProgressBarHelperMixin`: the boss health bar above the hotbar while it's shown.
- `ChatMixin` (with `ChatInput`, `CommandPopup`): the chat input.
  Terraria's `GetInputText` call in `DoUpdate_HandleChat` goes to `ChatInput.Edit`, which handles the cursor, selection, clipboard, word deletion and sent-message history itself and gives Terraria only the text before the cursor (so typing, Backspace and IME work there), with Ctrl, Insert and Delete hidden from it; Backspace over a selection is shown to it as already held.
  The chat monitor's `Offset` call scrolls by Page Up, Page Down and the wheel instead of Up and Down.
  The selection is drawn behind the input's text (before its `DrawColorCodedStringWithShadow`), and the completion's grey rest and then the cursor after `DrawPlayerChat` (vanilla's `|` is emptied), the cursor's blink timed by the clock and restarted by every change.
  `CommandPopup` shows the Aether API's `CommandCompletion.Complete` for the text and cursor (again whenever either changes, except after its own completion, whose list Tab keeps cycling, or a recalled message), polling the task, which a mod's suggestion provider can leave unfinished.
  Its popup is a Gum overlay screen (`CommandPopupScreen`, `fresh-ui:command-popup`): the suggestions in view in a `FreshPanel` under the word being completed, the selected one gold (hovering selects, a click completes, the wheel scrolls the list rather than the chat), its description in a panel beside it, or the usage or parse error; the grey rest of the selected suggestion after the typed text is still drawn with the input's text. The input line itself stays the game's (`ChatManager` draws chat tags, item icons among them, which Gum's text doesn't).
- `UIPanelMixin`, `UtilsMixin` (with `PanelArt`): the game's screens in FreshUI's (Gum's) style. Every `UIPanel` is drawn on whole UI pixels (its edges at even UI units, moved inwards so a row at a list's clipped edge keeps its border), as Gum lays everything out, so its 2×2-texel art stays even; and the character-creation panels the creation screens' option buttons, name fields and description boxes are drawn with (`Utils.DrawSplicedPanel` with `CharCreation/PanelGrayscale`, `CategoryPanelHighlight` or `CategoryPanelBorder`) are `FreshPanelButton`'s art: the panel art in the button's tint with a black border, and a selected or hovered rim over the panel just drawn as a gold border at its edge (a rim's art on its own, a description's box, a plain panel).
- `UILinkPointNavigatorMixin`, `UILinkPageMixin` (with `GumHudFocus`): the gamepad on the HUD by Gum's focus. Every control the HUD presents places the game's gamepad point for it (`SetPosition`, recorded), and each point placed this update (on the game's in-game pages, under 1000, the journey powers menu's, 1005, and the hotbar lock's) gets an invisible focus target there (a Forms control in a zone of the HUD screen); the D-pad and left stick move the focus to the nearest shown target that way (Gum's `SpatialNavigationService`), the game's own travel being off, and the game's navigator goes to the focused target's point (`ChangePoint`), so its cursor follows the focus and A, the slots' actions and the instruction bar's hints stay the game's; where the game moves its point itself (opening a page, a recipe's craft slot) the focus follows. The crafting pages (9 to 11), which move through recipes themselves, keep the game's travel. The Gum slots show the gamepad's slot with the gold outline (`FreshItemSlot.IsGamepadFocused`), and the hotbar lock, a Gum button, has a point on a page of its own (31300), lit while the gamepad's on it, A toggling it. (Gum's focus doesn't clear the last element's: `GumHudFocus` clears it, as Gum's own moves do.)
- `GlyphSnippetMixin`: a button glyph in text (the instruction bar) is centred on the text's capitals (Andy Bold's, `SdfText.MouseTextCapMiddle`) on whole UI pixels, not hung from the line's top.
- `MouseTextMixin` (with `TooltipText`): hover text and tooltips (an item's, a buff's, a name under the cursor) in Gum's text. The game still works out each line, its colour and place, and draws the box (a `FreshPanel`, `UtilsMixin`); each line's draw (`DrawColorCodedStringWithShadow` in `MouseTextInner` and `MouseText_DrawItemTooltip`, the buff tooltip's own outlined `DrawString`, its shadow passes dropped) is collected instead, and at each return of `MouseTextInner` they're drawn on the spot (`GumInline`) as Andy Bold at the game's mouse text size (9.5 UI pixels, 19 units an em), on its baseline. Lines with chat tags (item icons, colour tags) stay the game's.
- `ChatInputBoxMixin` (with `ChatInputBox`): the chat input's box (the game's `TextBack` strip) is the text field's panel being typed in (lit, gold border), drawn on the spot under the game's line, which keeps its chat tags.
- `InstructionBarMixin`: the gamepad's instruction bar (its button hints) has a drop shadow under its outlined text and glyphs, as the hotbar's numbers: the same text a UI pixel lower in black at alpha 100, drawn first.
- `GameTipsDisplayMixin`: the loading tips (under the world generation's progress) have the instruction bar's drop shadow, drawn first under their outlined text; they stay the game's chat text, as they can hold glyph tags.
- `CursorMixin` (with `PixelCursor`): the cursor's sprites (the cursor, its shadow, the thick cursor's outline, the gamepad's cursors) at integer scaling: a whole number of screen pixels per texel (the UI scale rounded, at least one), point-sampled (`Texture.SamplerEXT`), from the cursor's point on a whole screen pixel, each sprite's offset from it scaled with it.
- `GameStateScreen` (`fresh-ui:game-state`, `GumRoutes.StateKind` on its list of types): the rest of the game's screens, each by `GameUiMirror` with nothing of its own to add: the Workshop (its hub, publishing a world or resource pack, importing worlds), resource packs (the list, a pack's information), the advanced world creation and its secret seeds, the gamepad bindings (`UIManageControls`, from the settings' Keybindings tab), and the debug and test states (world generation debug, debug commands and loadouts, reports, text wrapping); on the title menu or as a fancy UI in game (over the game dimmed), B the game's back.
- `BestiaryScreen` (`fresh-ui:bestiary`, `GumRoutes.State<UIBestiaryTest>`, a fancy UI from the inventory's bestiary button, modal over the game dimmed): the bestiary by `GameUiMirror`: its search, the unlocks and filters buttons and their option grids, the entries' grid (each entry's portrait and number drawn by the game, a click selecting it) and its pages, and the chosen entry's information (name, portrait, description, kills, where it lives) in a `FreshScrollViewer`; the gamepad by Gum's focus. For it, `GameUiMirror` keeps each element's component across rebuilds (a control being pressed survives the hover borders an entry adds and removes), rebuilds when the tree's elements change by identity (a page's new entry buttons, as many as before) and then lays out the screen's children, not the screen (the bestiary's own `Recalculate` refills its grid and drops the selection), draws image buttons with children whole, and gives a panel the game's border colour; on the HUD (`PanelsTakeMouse`, the journey powers) panels take the mouse where the game's do, so clicks on them don't reach the world.

- `EmotesScreen` (`fresh-ui:emotes`, `GumRoutes.State<UIEmotesMenu>`, a fancy UI from the inventory's emote button, modal over the game dimmed): the emotes in the menus' window ("Emotes", FreshUI's own English: the game's menu has no title): the game's groups (its private lists, by reflection, so the critters and bosses are as the world has met them) under muted headers, each emote a Forms button in its bubble, animated as the game's (two frames, ten updates each), its border gold (`Main.OurFavoriteColor`) while hovered or focused, its "/name" as its tooltip and label; a click or A emotes (`EmoteBubble.MakeLocalPlayerEmote`) and closes the menu. - `AchievementsScreen` (`fresh-ui:achievements`, `GumRoutes.State<UIAchievementsMenu>`, on the title menu and as a fancy UI in game, modal over the game dimmed; `UIAchievementsMenuMixin`): the achievements in the menus' window (`FreshWindow.PlaceAsMenu`, shared with the Mods window): the four categories as `FreshIconButton` toggles filtering the list (all on as each opening starts, as the game's; their names as tooltips), a row per achievement in the game's order (its icon, locked or not, in its border; its name in gold once completed, silver before, with its category's icon; its tracker's count and a `FreshProgressBar` while locked; its description), lit while hovered, and Back (the main menu, or in game the pause menu); Esc and B go back on the title menu. The game's `GotoAchievement` (an "achievement unlocked" notification's click) scrolls Gum's list to the achievement's row.
- `UIEquipToggleMixin`: an equipment slot's corner toggle (accessory, pet and light visibility), which the game draws before Gum draws the slots, is drawn over them (`HudScreen.DrawOver`: a `FreshGameView` last among the HUD's children); its input stays the game's.
- `UtilsMixin` (with `InventoryBox`): the game's boxes are FreshUI's panel, drawn by Gum on the spot (`GumInline`: an element on a layer of its own, drawn within the game's sprite batch where the game drew its box, so the game's content on it draws over it as before): `Utils.DrawInvBG` (tooltips' opaque box, popups, capture mode) draws a `FreshPanel` in its colour (its border black at the colour's alpha) wherever the batch is in UI space and the box is at least the panel's corners (12 units) both ways; elsewhere it keeps the game's art.
- Mixin code can't reference Aether's `internal` types, so it reaches them through selectors, `[Shadow]` and return values instead.
